# node-gles3 Architecture

A native Node.js module providing WebGL2-compatible OpenGL ES 3 bindings, along with windowing (GLFW), VR (OpenVR), video texture sharing (Spout), depth cameras (Intel RealSense, Stereolabs ZED), and audio (miniaudio / genish.js) support.

## High-Level Overview

```
+-------------------------------------------------------------------+
|                        JavaScript API                              |
|  index.js, gles3.js, glfw3.js, openvr.js, spout.js, audio.js      |
+-------------------------------------------------------------------+
|                       Utility Layer                                |
|  glutils.js (VAO, FBO/G-buffer, textures, shaders, geometry)      |
|  window.js (multi-window management)                              |
|  shadertoy.js, shaderman.js (shader hot-reload & multi-pass)      |
|  genish.js, genish-worker.js (worker-thread DSP audio synthesis)  |
+-------------------------------------------------------------------+
|                    Native Bindings (N-API)                         |
|  node-gles3.cpp, node-glfw3.cpp, node-openvr.cpp,                 |
|  node-spout.cpp, node-audio.cpp, node-realsense.cpp, node-zed.cpp |
+-------------------------------------------------------------------+
|                    Native Libraries                                |
|  GLEW, GLFW3, OpenVR, SpoutLibrary, miniaudio, RealSense, ZED SDK |
+-------------------------------------------------------------------+
```

## Core Components

### 1. Native Bindings (`src/`)

The C++ native modules use Node-API (both raw C `node_api.h` via `src/node-api-helpers.h` and C++ `node-addon-api` `napi.h`) to expose native graphics, audio, and sensor libraries to JavaScript.

| Module | Source | N-API Layer | Purpose |
|--------|--------|-------------|---------|
| `gles3.node` | `node-gles3.cpp`, `node-gles3.h` | C `node_api.h` | OpenGL ES 3.0 / WebGL2 API (backed by GLEW + desktop OpenGL 3.3 Core) |
| `glfw3.node` | `node-glfw3.cpp`, `node-glfw3.h` | C `node_api.h` | Window creation, monitor queries, input callbacks, context management |
| `openvr.node` | `node-openvr.cpp`, `node-openvr.h`, `vr.h` | C `node_api.h` | Desktop VR headset & controller support (SteamVR) with WebXR-like input |
| `spout.node` | `node-spout.cpp` | `node-addon-api` | Windows-only OpenGL texture/FBO sharing (`Sender`, `Receiver`) |
| `audio.node` | `node-audio.cpp` | `node-addon-api` | Cross-platform duplex audio ringbuffer via `miniaudio` |
| `realsense.node` | `node-realsense.cpp` | `node-addon-api` | Intel RealSense depth camera (`Pipeline` pointcloud, mesh & voxelizer) |
| `zed.node` | `node-zed.cpp` (in `binding1.gyp`) | `node-addon-api` | Stereolabs ZED stereo depth camera (`Camera` pointcloud & normals) |

**Code Generation**: Native bindings for `gles3`, `glfw3`, and `openvr` are auto-generated by `tools/gen.js` during `npm install`:
- Parses C headers (`src/GLES3/gl3.h`, `src/GLES3/gl2ext.h`, `GLFW/glfw3.h`) and `openvr_api.json`
- Scans hand-written headers (`src/node-gles3.h`, `src/node-glfw3.h`, `src/node-openvr.h`) to avoid overwriting custom N-API functions and applies a symbol blacklist for functions absent from pre-built libraries
- Outputs C++ addon sources (`src/node-gles3.cpp`, `src/node-glfw3.cpp`, `src/node-openvr.cpp`) and JavaScript wrapper/constant modules (`gles3.js`, `glfw3.js`, `openvr.js`)

### 2. JavaScript API Layer

**Entry Point**: `index.js`
```javascript
const gl = require("./gles3.js")
const glfw = require("./glfw3.js")
gl.glfw = glfw;
module.exports = gl;
```

**Module Structure**:
- `gles3.js` - Generated OpenGL ES 3 constants and functions (WebGL2-compatible naming, plus `gl.glewInit()`)
- `glfw3.js` - Generated GLFW3 windowing constants and functions
- `openvr.js` - Generated loader for `openvr.node` (`connect`, `update`, `inputSources`, `getTextureWidth`, `getTextureHeight`, `getView`, `getProjection`, `submit`, `getModelNames`)
- `spout.js` - Loader for `spout.node` exposing `Sender` and `Receiver` classes (Windows)
- `audio.js` - Loader for `audio.node` exposing `devices`, `start()`, `end()`, `t`, `samplerate`, `inbuffer`, `outbuffer`, and `pollms`
- `realsense.node` / `zed.node` - Loaded directly via `require('bindings')('realsense.node')` or `require('bindings')('zed.node')`

### 3. Utilities Layer (`glutils.js`)

High-level abstractions over raw GL calls:

| Function | Purpose |
|----------|---------|
| `makeProgram()`, `createShader()`, `createProgram()` | Compile and link shaders with automatic uniform parsing and line-annotated error logs |
| `createVao()`, `createQuadVao()`, `makeBuffer()` | Create Vertex Array Objects and GPU buffers from geometry objects |
| `createInstances()` | Manage interleaved instanced vertex buffers and attach divisors to VAOs |
| `createTexture()`, `createPixelTexture()`, `createCheckerTexture()` | Create 2D textures (uint8 or float32, optional multisampling & mipmaps) |
| `createTexture3D()` | Create 3D volume textures (`TEXTURE_3D`) |
| `img2tex()`, `loadTexture()` | Load PNG (`pngjs`) and JPEG (`jpeg-js`) images into 2D textures |
| `createFBO()` | Ping-pong (`front`/`back`) framebuffer with multisampled renderbuffer |
| `makeFboWithDepth()` | Framebuffer with color and depth textures (optional multisampling) |
| `makeGbuffer()` | Multi-render-target (MRT) G-buffer with configurable float/uint8 attachments and depth |
| `createSlab()` | Fullscreen quad post-processing pass wrapper |
| `makeCube()`, `makeQuad()`, `makeQuad3D()`, `makeLine()`, `makeOpenCylinder()` | Procedural geometry generators |
| `geomFromOBJ()`, `geomFromGLTF()` / `geomFromGLB()`, `geomAppend()`, `geomTransform()`, `geomTexTransform()` | Wavefront OBJ and glTF/GLB 2.0 mesh loaders (including `KHR_draco_mesh_compression` via `lib/draco/`) and CPU-side geometry transformation/merging utilities |
| `quat_rotate()`, `quat_unrotate()`, `quat_rotation_to()` | Quaternion vector rotation helpers (complementing `gl-matrix`) |
| `ok()`, `requestAnimationFrame()` | GL error logging helper and `process.hrtime`-based animation timer |

**Uniform Handling**: Shader uniforms are automatically extracted via regex parsing (`uniformsFromCode()`) and wrapped with chainable, type-aware setters (`program.uniform(name, ...)`).

### 4. Window Management (`window.js`)

The `Window` class provides:
- Automatic GLFW initialization, OpenGL 3.3 Core Profile context creation (4x MSAA), and `gl.glewInit()`
- Multi-window support (`Window.all`) with shared GL contexts (all subsequent windows share the first window's context)
- Borderless fullscreen toggle (`toggleFullscreen()`, `setFullscreen()`) and monitor selection
- Input callbacks (`onkey`, `onpointermove` with normalized `[-1, 1]` coordinates, `onpointerbutton`, `onpointerscroll`)
- Static render loop (`Window.animate()`) with per-window timing (`t`, `dt`, `fps`, `frame`) and optional FPS cap (`Window.syncfps`)

```javascript
const Window = require('./window.js')
let win = new Window({
    title: "My App",
    fullscreen: false,
    draw(gl) { /* render code */ }
})
Window.animate()
```

### 5. Shader & Audio Tools

- **`shadertoy.js`**: Multi-pass Shadertoy-compatible environment (`Shadertoy` class) supporting up to 4 buffer passes with `RGBA32F` ping-pong textures, standard uniforms (`iResolution`, `iTime`, `iTimeDelta`, `iFrameRate`, `iFrame`, `iDate`, `iMouse`, `iChannel0..3`), and automatic file hot-reloading.
- **`shaderman.js`**: Shader file manager (`Shaderman` `EventEmitter`) that loads `.vert.glsl` / `.frag.glsl` pairs from a folder, resolves `#include "..."` directives, tracks include dependencies, and hot-reloads modified shaders via `fs.watch`.
- **`genish.js` & `genish-worker.js`**: Single-sample DSP graph synthesis library running in a Node.js `worker_threads` worker, feeding `audio.node`'s ringbuffers with state preservation and crossfading across live graph edits.
- **`docs/THREEJS_REF.md`**: Reference design for polyfilling browser globals (`window`, `document`, `requestAnimationFrame`, textures, DOM input events) to run Three.js scenes natively on `node-gles3`.

## Build System

**`binding.gyp`** defines 6 native module targets (`gles3`, `glfw3`, `openvr`, `audio`, `realsense`, `spout`):
- **macOS (`OS=="mac"`)**: Links against Homebrew libraries in `/opt/homebrew/include` and `/opt/homebrew/lib` (`-lGLEW`, `/opt/homebrew/lib/libglfw3.a`, `-framework OpenGL`, `-framework Cocoa`) for Apple Silicon / ARM64 support. (`binding1.gyp` retains the legacy Intel macOS paths using `native-graphics-deps` as well as the experimental `zed` target.)
- **Linux (`OS=="linux"`)**: Links system `-lGLEW`, `-lGL`, and `-lglfw`.
- **Windows (`OS=="win"`)**: Links pre-built binaries from `native-graphics-deps`, `native-openvr-deps`, `lib/x64/SpoutLibrary.lib`, and Intel RealSense SDK 2.0, copying runtime `.dll` files into `./build/<CONFIGURATION_NAME>/`. (On non-Windows platforms, `realsense` and `spout` build as empty stub targets.)

**Install Script** (`package.json`):
```bash
node tools/gen.js && mkdir -p build/node_gyp_bins && node-gyp rebuild
```

**Dependencies** (via npm):
- `bindings` - Native `.node` addon resolution
- `node-addon-api` (`^8.7.0`) - C++ N-API header-only helpers
- `native-graphics-deps` - Pre-built GLEW/GLFW headers and Windows/Intel macOS binaries
- `native-openvr-deps` - OpenVR SDK headers and binaries
- `gl-matrix` - Vector/matrix math
- `pngjs`, `png-js`, `jpeg-js` - Image decoding
- `rtsp-stream`, `yellowstone` - RTSP video streaming support (used in `example-rtsp2texture.js`)
- `zed` - ZED camera package dependency

## Data Flow

### Typical Render Frame

```
1. glfw.pollEvents()           # Process OS events & fire window callbacks
2. For each win in Window.all:
   +-- Check glfw.windowShouldClose() / ESC key
   +-- win.render(gl):
       +-- Update dt, fps, t
       +-- glfw.makeContextCurrent(win.window)
       +-- win.draw(gl):
           +-- gl.viewport(), gl.clear()
           +-- program.begin()
           +-- program.uniform(...)
           +-- vao.bind().draw().unbind()
           +-- program.end()
       +-- glfw.swapBuffers(win.window)
       +-- Increment win.frame
3. setImmediate(Window.animate) # (or setTimeout if Window.syncfps is set)
```

### VR Rendering (Side-by-Side Stereo FBO)

```
1. vr.connect(true)            # Initialize SteamVR & compositor
2. Allocate stereo FBO of size [vr.getTextureWidth(), vr.getTextureHeight()]
   (width is 2x single-eye width for side-by-side rendering)
3. Each frame:
   +-- vr.update()             # WaitGetPoses & update vr.inputSources()
   +-- gl.bindFramebuffer(gl.FRAMEBUFFER, fbo.id)
   +-- For eye = 0, 1:
       +-- gl.viewport(eye * fbo.width/2, 0, fbo.width/2, fbo.height)
       +-- vr.getView(eye, viewMatrix)
       +-- vr.getProjection(eye, projMatrix)
       +-- Render scene & controllers (from vr.inputSources())
   +-- gl.bindFramebuffer(gl.FRAMEBUFFER, null)
   +-- vr.submit(fbo.colorTexture) # Submits left (0..0.5) & right (0.5..1) bounds
```

### macOS (Apple Silicon / Homebrew)

`binding.gyp` expects `glew` and `glfw` installed via Homebrew under `/opt/homebrew`:

```bash
brew install glew glfw
npm install
```

### aarch64 Linux

Use the dedicated build script instead of standard `npm install` scripts:

```bash
sudo apt install libglew-dev libglfw3-dev libgl1-mesa-dev
npm install --ignore-scripts
./build-aarch64.sh
```

This runs `tools/gen.js` (copying system `/usr/include/GLFW/glfw3.h` if needed) and builds with `binding-linux-arm64.gyp`, which compiles only the supported cross-platform modules (`gles3`, `glfw3`, `audio`).

## Key Design Decisions

1. **WebGL2 Compatibility**: JavaScript GL API mirrors WebGL2 method names and signatures for straightforward porting of browser shaders and rendering code (including Three.js).
2. **Header-Driven Code Generation**: `tools/gen.js` auto-generates 300+ GL and GLFW N-API bindings directly from C headers while allowing hand-written overrides in `src/node-*.h`.
3. **ABI Stability via N-API**: Uses Node-API (`node_api.h` and `node-addon-api`) to maintain binary compatibility across Node.js versions.
4. **Shared GL Contexts**: Multi-window setups automatically share the primary window's OpenGL context so textures, buffers, and shaders can be reused across windows.
5. **Non-Blocking Event & Audio Loops**: Uses `setImmediate()` for the main render loop to keep Node.js I/O responsive, and ringbuffers + `worker_threads` for glitch-free audio synthesis.
