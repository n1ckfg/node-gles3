# node-gles3 Architecture

A native Node.js module providing WebGL2-compatible OpenGL ES 3 bindings, along with windowing (GLFW), VR (OpenVR), video sharing (Spout), and audio support.

## High-Level Overview

```
+-------------------------------------------------------------------+
|                        JavaScript API                              |
|  index.js, gles3.js, glfw3.js, openvr.js, spout.js, audio.js      |
+-------------------------------------------------------------------+
|                       Utility Layer                                |
|  glutils.js (VAO, textures, shaders, geometry)                    |
|  window.js (multi-window management)                              |
|  shadertoy.js, shaderman.js (shader tools)                        |
+-------------------------------------------------------------------+
|                    Native Bindings (N-API)                         |
|  node-gles3.cpp, node-glfw3.cpp, node-openvr.cpp,                 |
|  node-spout.cpp, node-audio.cpp, node-realsense.cpp               |
+-------------------------------------------------------------------+
|                    Native Libraries                                |
|  GLEW, GLFW3, OpenVR, SpoutLibrary, miniaudio, RealSense SDK      |
+-------------------------------------------------------------------+
```

## Core Components

### 1. Native Bindings (`src/`)

The C++ native modules use N-API to expose native graphics libraries to JavaScript.

| Module | Source | Purpose |
|--------|--------|---------|
| `gles3.node` | `node-gles3.cpp` | OpenGL ES 3.0 / WebGL2 API |
| `glfw3.node` | `node-glfw3.cpp` | Window creation, input, context management |
| `openvr.node` | `node-openvr.cpp` | Desktop VR headset support (SteamVR) |
| `spout.node` | `node-spout.cpp` | Windows-only video texture sharing |
| `audio.node` | `node-audio.cpp` | Cross-platform audio via miniaudio |
| `realsense.node` | `node-realsense.cpp` | Intel RealSense depth camera |

**Code Generation**: Native bindings for `gles3` and `glfw3` are auto-generated by `tools/gen.js`, which parses the GLES3 and GLFW header files and generates both:
- C++ wrapper code (`node-gles3.cpp`, `node-glfw3.cpp`)
- JavaScript constant exports (`gles3.js`, `glfw3.js`)

Hand-written portions reside in header files (`node-gles3.h`, `node-glfw3.h`) for functions requiring custom handling.

### 2. JavaScript API Layer

**Entry Point**: `index.js`
```javascript
const gl = require("./gles3.js")
const glfw = require("./glfw3.js")
gl.glfw = glfw;
module.exports = gl;
```

**Module Structure**:
- `gles3.js` - OpenGL ES 3 constants and functions (WebGL2-compatible)
- `glfw3.js` - GLFW3 windowing constants and functions
- `openvr.js` - OpenVR bindings for VR headsets
- `spout.js` - Spout texture sharing (Windows)
- `audio.js` - Audio playback via miniaudio

### 3. Utilities Layer (`glutils.js`)

High-level abstractions over raw GL calls:

| Function | Purpose |
|----------|---------|
| `makeProgram()` | Compile and link shaders with automatic uniform parsing |
| `createVao()` | Create Vertex Array Objects from geometry |
| `createTexture()` | Create 2D textures with various formats |
| `createFbo()` | Create framebuffer objects for render-to-texture |
| `makeCube()`, `makeQuad()` | Generate common geometry |
| `img2tex()` | Load PNG/JPEG images as textures |

**Uniform Handling**: Shader uniforms are automatically extracted via regex parsing and wrapped with type-aware setters (`uniform1f`, `uniformMatrix4fv`, etc.).

### 4. Window Management (`window.js`)

The `Window` class provides:
- Multi-window support with shared GL contexts
- Fullscreen toggle and monitor selection
- Input callbacks (keyboard, mouse, scroll)
- Render loop with timing (`dt`, `fps`, `frame`)

```javascript
const Window = require('./window.js')
let win = new Window({
    title: "My App",
    fullscreen: false,
    draw(gl) { /* render code */ }
})
Window.animate()
```

### 5. Shader Tools

**shadertoy.js**: Shadertoy-compatible environment for running fragment shaders with standard uniforms (`iResolution`, `iTime`, `iMouse`, etc.) and multi-pass rendering.

**shaderman.js**: Shader file manager with hot-reloading support.

## Build System

**`binding.gyp`** defines native module targets:
- Conditional compilation for macOS, Linux, Windows
- Library linking (GLEW, GLFW, OpenGL, OpenVR, etc.)
- DLL copying for Windows runtime dependencies

**Dependencies** (via npm):
- `native-graphics-deps` - Pre-built GLEW/GLFW binaries
- `native-openvr-deps` - OpenVR SDK
- `node-addon-api` - N-API helper macros
- `gl-matrix` - Vector/matrix math
- `pngjs`, `jpeg-js` - Image loading

## Data Flow

### Typical Render Frame

```
1. glfw.pollEvents()           # Process OS events
2. Window.render()             # For each window:
   +-- glfw.makeContextCurrent()
   +-- user draw() callback:
       +-- gl.viewport(), gl.clear()
       +-- program.begin()
       +-- program.uniform(...)
       +-- vao.bind().draw()
       +-- program.end()
   +-- glfw.swapBuffers()
3. setImmediate(animate)       # Schedule next frame
```

### VR Rendering

```
1. vr.update()                 # Get headset/controller poses
2. For each eye:
   +-- fbo.begin()
   +-- vr.getViewMatrix(eye)
   +-- vr.getProjectionMatrix(eye)
   +-- render scene
   +-- fbo.end()
3. vr.submit(leftTex, rightTex)
```

## Key Design Decisions

1. **WebGL2 Compatibility**: API mirrors WebGL2 for easy porting of browser code
2. **Code Generation**: Reduces maintenance burden for 300+ GL functions
3. **N-API**: Provides ABI stability across Node.js versions
4. **Shared Contexts**: Multiple windows share a single GL context for resource sharing
5. **Immediate Mode Loop**: Uses `setImmediate()` for render loop to remain responsive to I/O
